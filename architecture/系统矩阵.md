# 系统矩阵设计

## 模块定位

系统矩阵是UHES的**系统资产登记中心**，统一登记全部生成的业务系统，维护范式标签、依赖关系、元数据，支持系统之间互相调用、互相校验。

是实现"系统生成系统"递归闭环的核心基础设施。

## 核心功能

1. **系统登记**：新生成系统自动注册，分配唯一ID
2. **范式标签**：自动注入系统使用的范式标签
3. **依赖关系**：记录系统之间的调用、依赖、验证关系
4. **检索查询**：按domain、范式、标签检索系统
5. **交叉验证**：调用矩阵内多系统对同一问题求解
6. **中心性分析**：分析系统在关系网络中的重要性

## 系统注册结构

每个注册系统包含：
```
{
  "system_id": "sys_investment_001",     // 唯一ID（固定语义ID）
```

## ID生成机制

### 初始机制（已修复）
```python
system_id = int(time.time())  # 秒级时间戳
```
**问题**：同一秒内注册多个系统会冲突（V4发现）

### 当前机制
核心业务系统使用**固定语义ID**：
```
sys_{domain}_{序号}
```
示例：
- sys_investment_001（投资分析系统）
- sys_novel_001（小说创作系统）
- sys_health_001（健康管理系统）
- sys_growth_001（个人成长系统）
- sys_active_inference_001（主动推理系统）

**优势**：
- 语义清晰，一看就知道是什么系统
- 不会冲突
- 便于记忆和引用

## 范式标签自动注入

### 机制
1. 蓝图生成器输出架构蓝图时，直接把本次融合的范式ID写入输出
2. 系统矩阵接收新系统注册，自动读取蓝图携带的范式元数据
3. 自动填充范式标签，不再手动录入

### 优势
- 避免手动录入错误
- 保证标签与实际使用范式一致
- 支持按范式检索系统

## 关系网络（扩展能力，默认关闭）

### 关系类型
1. **依赖关系**：A系统运行需要B系统提供数据/能力
2. **调用关系**：A系统在工作流中调用B系统
3. **验证关系**：A系统的输出被B系统验证过
4. **同构关系**：A系统与B系统在结构/动力学上存在同构

### 中心性分析
- **度中心性**：系统直接连接的数量
- **介数中心性**：系统在最短路径上出现的频率
- **接近中心性**：系统到其他系统的平均距离

用于识别核心系统、瓶颈系统、孤立系统。

## 交叉验证引擎

### 工作机制
1. 接收一个问题
2. 从系统矩阵中检索3-5个相关系统
3. 分别调用这些系统求解
4. 对比各系统输出
5. 输出结论置信度

### 置信度计算
- 全部系统结论一致 → 高置信度
- 多数系统结论一致 → 中置信度
- 结论严重分歧 → 低置信度，需人工介入

### 待验证

## 系统组合自动编排（扩展能力，默认关闭）

### 功能
依据任务自动调度多系统协同，自动编排工作流。

### 示例
任务："分析某只股票并生成投资报告"
自动编排：
1. 调用sys_data_001获取行情数据
2. 调用sys_fundamental_001做基本面分析
3. 调用sys_technical_001做技术面分析
4. 调用sys_risk_001做风险评估
5. 调用sys_report_001生成最终报告

## 矩阵查询路由（V7重构）

### 重构前
_handle_query方法：100行if-elif链，圈复杂度39

### 重构后
26行字典映射，圈复杂度3（降低92%）

```python
# 重构后的路由结构
QUERY_HANDLERS = {
    "register": self._handle_register,
    "query": self._handle_query_system,
    "list": self._handle_list,
    "update": self._handle_update,
    "archive": self._handle_archive,
    "search_by_paradigm": self._handle_search_by_paradigm,
    "search_by_domain": self._handle_search_by_domain,
    "get_relations": self._handle_get_relations,
    "centrality_analysis": self._handle_centrality,
    # ...
}

def handle_query(self, query_type, **kwargs):
    handler = self.QUERY_HANDLERS.get(query_type)
    if handler:
        return handler(**kwargs)
    else:
        return {"error": f"Unknown query type: {query_type}"}
```

## 沙箱环境适配

- 系统矩阵登记清单属于永久层，可通过记忆匣完整迁移
- 关系网络缓存属于临时层，沙箱回收后重置
- 中心性分析结果属于临时层，可重新计算

## 递归闭环

系统矩阵是"系统生成系统"递归闭环的关键：
1. 范式演化设计师生成新系统
2. 新系统自动登记进入系统矩阵
3. 矩阵内系统可被再次拿来迭代优化
4. 迭代后的系统更新登记信息
5. 形成持续进化的系统生态

> 待验证：递归闭环能否实现有价值的二次进化，而不是简单重复（见待验证预测5）
