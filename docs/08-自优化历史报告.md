## V4 第四轮自优化（工程bug大修复）

### 审计发现
| 问题 | 严重度 |
|------|--------|
| cross_evolution.py双重plugins路径bug | 🔴高 |
| 2262条测试数据膨胀（数据库2.7MB） | 🟡中 |
| 生成器可产生"未命名系统"垃圾插件 | 🟡中 |
| 矩阵系统ID同一秒注册冲突 | 🟡中 |
| plugin_general反复被测试生成 | 🟢低 |
| evolution_history_old旧表残留 | 🟢低 |

### 执行修复

**1. 路径bug根因修复（P0）**
- cross_evolution.py中workspace_root只取了3次dirname（得到plugins/），应为4次
- 导致数据库被创建在plugins/plugins/plugin_auto_evolution/storage/
- 已迁移数据库到正确位置，清理双重plugins目录

**2. 生成器输入验证（P1）**
- 新增_get_supported_domains()方法
- 当domain为"通用"且名称为"未命名系统"时，返回needs_clarification提示
- 修复了"系统生成器"帮助请求被误拦截的问题

**3. 矩阵ID冲突修复（P1）**
- register_system用int(time.time())生成ID，同一秒内注册多个系统会冲突
- 核心业务系统改用固定语义ID（sys_investment_001等）

**4. 数据清理（P2）**
- 清理9个数据库中共2262条测试记录
- 数据库总大小从2.7MB降至272KB（-90%）
- 删除evolution_history_old旧表
- VACUUM回收空间

**5. 插件生成逻辑根因修复**
- 问题：plugin_id = f"plugin_{en_name}_{时间戳后4位}"，每次生成都创建新目录
- 修复：改为固定命名，同名插件自动备份到archive/plugin_backups/后覆盖

### 优化效果
| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 插件数 | 26 | 22 |
| 数据库大小 | 2.7MB | 272KB |
| 测试通过率 | - | 100% S级 |

### 状态
- 插件22个（12核心 +9业务 +1研究池）
- 进化记忆8条
- 31位虚拟专家，581对同构关系
- 30条方法论，7条被实际调用
- 综合健康度86/100

## V5 第五轮精细收敛自优化（底座冻结）

### 审计发现
- 进化记忆只有1条记录，系统几乎没有学习积累
- 插件调度层异常回落逻辑单薄
- 系统矩阵新生成业务系统范式标签不会自动注入
- 方法论库缺少调用埋点

### 执行优化

**1. 进化记忆检索增强**
- 新增标签加权过滤：检索优化经验时优先匹配当前任务的范式标签
- 不改动原有存储表结构，新增查询参数

**2. 调度层降级保护**
- 插件运行抛出异常时，新增三级降级：
  ① 捕获异常，记录故障日志
  ② 尝试调用该插件的备用轻量版本
  ③ 备用版本失效，返回可控业务提示

**3. 蓝图生成器联动矩阵自动打范式标签**
- 蓝图生成器输出架构蓝图时，直接把本次融合的范式ID写入输出
- 系统矩阵接收新系统注册，自动读取蓝图携带的范式元数据

**4. 方法论埋点统计**
- 每一次方法论管家输出并被业务插件使用，记录场景ID、方法论ID、任务描述

### 重要决策
**底座到此收敛，不再新增底层大功能；后续全部精力投入上层业务智能体开发。**

### 结果
- 综合健康度89/100 🟢健康
- 105项测试全量S通过
- 进化记忆9条

## V8 第八轮沙箱适配自优化（快照机制）

### 核心审计命题
适配**临时动态沙箱环境、无自动持久化、闲置资源回收**底层约束，重构UHES状态管理机制。

### 基线现状扫描
| 项目 | 当前情况 | 风险等级 |
| ---- | ---- | ---- |
| 运行载体 | 会话内存沙箱，无磁盘落地 | 🔴高风险 |
| 静态资产 | 可写入记忆匣迁移 | 🟢安全 |
| 动态运行数据 | 沙箱销毁全部清零 | 🔴高风险 |
| 自优化流程 | 缺少标准化快照模板 | 🟡中风险 |
| 跨会话恢复能力 | 仅能重建架构 | 🟡中风险 |

### 专家圆桌共识
1. 必须严格拆分两类数据，执行分层管理
   - **永久层（可序列化，纳入记忆匣）**：架构契约、范式全集、专家定义、方法论文本、自优化报告、进化记忆、系统矩阵清单
   - **临时层（内存瞬时数据，不跨会话保留）**：实时调用计数器、检索缓存、专家临时草稿、实时健康度浮动指标
2. 每一轮审计&优化完成，自动生成标准化文本快照
3. 弱化连续统计指标权重，不再作为系统健康度硬性扣分标准
4. 新增沙箱降级策略：检测会话长时间无交互，主动输出当前快照摘要
5. 禁止设计依赖"长期驻留、持续累积状态"的远期功能

### 执行优化

**P0 核心优化**
1. 数据分层规范写入系统底层契约
2. 新增「优化快照自动生成器」内嵌自优化流程尾部

**P1 机制优化**
1. 调整方法论管家逻辑：累计调用统计仅为本会话参考
2. 专家圆桌缓存自动清理规则：单次会诊结束后清理中间草稿

**P2 预留扩展接口**
预留手动快照导出触发入口（默认关闭）

### 优化效果
| 指标 | V7基线 | V8结果 |
|------|--------|--------|
| 综合健康度 | 87/100 | 88/100 |
| 进化记忆 | 10条 | 11条 |
| 测试通过率 | 100% | 100% S级 |
| 上下文冗余风险 | 中等 | 降低 |
