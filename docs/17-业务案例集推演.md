# 17. 业务案例集推演（数据分析平台 · 知识管理 Agent）

> 文档性质声明:本文档记录 UHES 概念原型上新增的两个业务案例全链路推演。
> 案例均走 S1→S8 八步状态机,产出 7 件套交付包样例;为概念推演,非真实运行。

## 1. 案例设计原则

- **复用冻结引擎**:不修改 PipelineStateMachine 与各 step 侧车主体,仅新增 demo 输入。
- **领域多样性**:学术研究(lit_review 基线) / 数据分析(analytics) / 知识管理(knowledge),
  验证状态机对不同领域需求的鲁棒性。
- **约束差异化**:三案例的硬约束、成功标准、范式线索各不相同,覆盖不同杂交路径。

## 2. 案例一:会话式数据分析平台(analytics)

### 2.1 需求(概念)

电商运营团队:自然语言提问 → 聚合结果+图表 → 异常主动预警。
核心要求:结论可追溯到数据切片(不能黑箱);轻量沙箱(不依赖商业 BI);
首期覆盖订单/流量/转化三主题。

### 2.2 推演要点

| 环节 | 推演 |
|------|------|
| S1 需求DNA | 硬约束:可解释性(结论带数据切片溯源)、沙箱轻量;软约束:三主题首期 |
| S2 范式匹配 | 数据分析领域 → 统计学/信息论/复杂系统范式;杂交:统计×信息论(结构同构) |
| S2.5 圆桌 | 匹配度高,跳过圆桌(roundtable_skipped_audit 记录理由) |
| S3 方法论 | 风险强制:异常预警高歧义 → 反例构造+鲁棒性边界测试 |
| S4 蓝图 | 会话式查询层 + 聚合引擎 + 预警器 + 溯源层 |
| S5 验证 | 8维评分:可解释性 S(每结论带切片),预警时效 B(概念层) |
| S6 交叉验证 | 与基线 lit_review 对照:数据溯源 vs 文献溯源,机制同构 |
| S7 验收 | success_criteria 逐条映射:可解释/轻量/三主题 全部覆盖 |
| S8 登记 | 写入矩阵 sys_analytics_001 |

### 2.3 运行结果

```bash
python3 main.py --case analytics
# 输出: 完整性 7件齐全=True | 全链路通过 verdict=deliver
```

## 3. 案例二:知识管理 Agent(knowledge)

### 3.1 需求(概念)

咨询团队:从邮件/文档/纪要自动抽取实体关系,构建可检索知识图谱;
记录每条知识来源与置信度;不覆盖历史版本;冲突标记争议而非静默合并。

### 3.2 推演要点

| 环节 | 推演 |
|------|------|
| S1 需求DNA | 硬约束:版本不覆盖、冲突标记争议;软约束:增量导入 |
| S2 范式匹配 | 知识管理 → 网络科学/认知科学/信息论;杂交:网络×信息论 |
| S2.5 圆桌 | 跨学科度高(网络+认知),触发圆桌召集;采纳"冲突双写"建议 |
| S3 方法论 | 图谱建模 + 因果依赖链追溯 + 版本快照哈希链 |
| S4 蓝图 | 抽取器 + 图谱存储(版本化) + 冲突仲裁器 + 召回接口 |
| S5 验证 | 8维评分:来源可溯 S(知识带来源文档ID),版本保持 S(快照链) |
| S6 交叉验证 | 与 analytics 对照:图谱溯源 vs 数据溯源,机制同构 |
| S7 验收 | success_criteria 逐条映射:召回完整率/来源可溯/版本不丢 全覆盖 |
| S8 登记 | 写入矩阵 sys_knowledge_001 |

### 3.3 运行结果

```bash
python3 main.py --case knowledge
# 输出: 完整性 7件齐全=True | 全链路通过 verdict=deliver
```

## 4. 三案例对照

| 维度 | lit_review(基线) | analytics | knowledge |
|------|-----------------|-----------|-----------|
| 领域 | 学术研究 | 数据分析 | 知识管理 |
| 硬约束 | 溯源到句子级 | 结论带数据切片 | 版本不覆盖/冲突标记 |
| 范式路径 | 信息论×科研 | 统计×信息论 | 网络×信息论 |
| 圆桌 | 触发(跨学科) | 跳过(高置信) | 触发(跨学科) |
| verdict | deliver | deliver | deliver |

## 5. 边界与说明

- 三案例共用冻结状态机,仅输入不同;验证的是**状态机对领域变化的鲁棒性**,非业务逻辑真实性。
- DNA 解析、范式匹配为概念模拟(规则化近似),真实实现需 NLP/检索/推理支撑。
- 案例矩阵登记(system id)为演示性写入,真实矩阵持久化属后续工程化议题。
