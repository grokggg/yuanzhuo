# 方法论管家运行机制

## 模块定位

统一管理整套方法论库，给插件、圆桌专家、自优化流程提供标准化思考工具，避免全靠直觉做架构与理论推演。

## 统称

整套方法论集合统称：**元方法工具箱（Meta-Method Toolkit）**

五大顶层分类作为一级目录，用于方法论管家做索引、路由、权限管控。

## 库规模

- **总计**：120+ 条细分方法论
- **常驻核心库**：30条高频方法（常驻内存，默认可用）
- **离线拓展库**：90+条（默认不载入主链路，按需调取）

## 五大顶层分类

### 1. 溯源分析类（底层公理挖掘）
定位问题根基、拆解前提、梳理因果依赖、区分定义与假设，适合理论构建、审计、逻辑校验。

**核心常驻（6条）**：
1. 第一性原理分析法
2. 公理拆解法
3. 因果依赖链追溯
4. 概念定义域审计
5. 边界条件提取法
6. 循环论证排查法

**拓展示例（离线）**：谱系溯源、根因五问、功能分解、本体建模等

---

### 2. 建模表征类（形式化/可计算转化）
把文字理论转为数学、网络、动力学模型，适配「范式可计算化、动力学等价杂交」需求。

**核心常驻（6条）**：
1. 动力学建模
2. 网络拓扑表征
3. 约束流形构建
4. 谱特征提取
5. 状态空间映射
6. 同构特征指纹化

**拓展示例（离线）**：微分方程建模、贝叶斯图构建、元胞自动机、马尔可夫表征等

---

### 3. 推理验证类（证伪、自检、交叉校验）
构造反例、对照实验、一致性检查、同行评议、全维度交叉验证，用于专家圆桌评审。

**核心常驻（7条）**：
1. 反例构造法
2. 公理自洽性检查
3. 可证伪预测构造
4. 奥卡姆剃刀（最小假设）
5. 交叉对照验证
6. 鲁棒性边界测试

**拓展示例（离线）**：归谬法、蒙特卡洛验证、敏感性分析、盲审评议等

---

### 4. 演化优化类（迭代闭环、自改进）
系统迭代、参数寻优、约束下搜索、自优化闭环、进化记忆归档，支撑UHES自我进化。

### 5. 协同编排类（多主体协作调度）
专家分工、任务拆分、冲突仲裁、同构匹配、组合编排，适配42专家圆桌、方法论管家调度。

**核心常驻（5条）**：

## 完整运行机制

### 1. 库分层存储结构

- **常驻核心库（30条）**：高频方法，常驻内存，随时调用
- **离线拓展库（90+）**：低频专业方法，平时不加载，收到明确调用指令才载入上下文，执行完成即释放，控制内存开销

### 2. 两种调用触发模式

**①主动调用**：用户或者插件显式指定"使用XX方法论"

**②被动推荐模式（主流）**：接收任务标签、圆桌专家输出意见，管家根据任务类型自动匹配输出候选方法论集合

示例：
- 专家指出该范式存在公理冲突 → 管家自动推送「公理自洽检查」
- 需要检验理论可靠性 → 推送「反例构造法、可证伪预测」
- 系统自优化 → 推送「技术债审计清理、增量重构法、快照断点回溯」

### 3. 方法论绑定执行模板

每一条方法论不是只有名字，附带标准化执行步骤模板。

**示例：反例构造法**
> 步骤1：提取理论全部前提与最终结论
> 步骤2：构造满足全部前提，但推导不出原有结论的极端边界场景
> 步骤3：判断反例是否有效，输出漏洞报告

**示例：第一性原理分析法**
> 步骤1：剥离所有既有假设和类比
> 步骤2：追溯到不可再分的基本公理
> 步骤3：从基本公理出发重新推导结论
> 步骤4：对比新结论与既有认知，识别差异

### 4. 埋点统计机制（V5新增）

管家记录：
- 哪一类任务
- 哪一个专家
- 调用了哪一套方法论
- 调用频次
- 产出有效缺陷数量

用途：后续分析哪些方法论真正发挥价值，哪些几乎没有被使用，反馈给自优化引擎。

### 5. 自优化自动记录（V6新增）

自优化流程新增`_record_methodology_usage`方法：
- 每次自优化自动记录使用的方法论并更新计数
- 根据优化内容智能匹配方法论：
  - 性能优化 → 梯度下降
  - 验证 → 对照实验
  - 架构 → 模块化设计
- 优化报告中展示"本次优化应用方法论"

### 6. 输出交付物

输出结构化方法论方案：
- 方法名称
- 执行步骤
- 适用边界
- 不适用场景

交付给蓝图生成器、理论融合引擎、自优化流程使用。
