## 第一部分：系统全貌

### 1.1 一句话定位

UHES（Universal Heterogeneous Evolution System，普适异构进化系统）是一个"系统生成系统"的元智能体——通过跨学科范式同构迁移与动力学等价杂交，从复杂现实需求中生成可落地的业务系统蓝图，并以系统矩阵登记实现递归自进化闭环。

### 1.2 核心理念：范式演化设计

| 维度 | 内容 | 实现程度 |
|------|------|----------|
| 跨学科同构迁移 | 29 组范式间建立 581 对结构同构关系，需求 DNA 经 embedding 检索匹配机制同构的范式（非关键词命中） | ✅ 已实现（第2项优化 embedding 化） |
| 动力学等价杂交 | 在结构同构基础上，挖掘底层演化规律/数学结构等价关系，进行深层杂交；默认关闭（扩展开关） | ✅ 已实现（阶段3扩展开关 + 第3项优化双通道校验） |
| 系统生成系统 | 产出系统入矩阵后可被再次迭代，实现递归闭环 | ✅ 已实现（阶段4 + 第12项进化闭环真实化） |

### 1.3 完整流水线 S1→S8

> ⚠️ 命名/顺序以代码实际注册顺序为准（build_pipeline 中 p.register 序列），与早期清单有出入。

| 步骤 | 实际名称 | 输入 | 输出 | 门控条件 |
|------|----------|------|------|----------|
| S1 | 需求DNA解析 | 用户原始需求（raw_requirement + context） | REQUIREMENT_DNA（goal/constraints/boundaries/risks/ambiguities/assumptions/paradigm_hints） | goal.primary 为空→FAIL澄清；硬约束冲突→FAIL裁决；歧义>阈值→澄清循环 |
| S2 | 范式匹配与杂交决策 | REQUIREMENT_DNA + 范式库 + 扩展开关 | MATCH_OUTPUT（matched_paradigms / recommended_methodologies / hybridization_decision / expert_roundtable_trigger / match_confidence） | matched_paradigms 为空→FAIL；branch=rejected→FAIL；动力学杂交自洽未通过→降级结构杂交 |

| S5 | 系统验证（8维评分） | 蓝图 + DNA | 验证报告（8维评分S/A/B/C/D + defect_list + gate_result + cross_validation并入） | critical缺陷→FAIL（回退S4≤1次）；缺陷总数>阈值→建议回退 |
| S6 | 交叉验证（可选） | 蓝图 + 系统矩阵相关系统 | 交叉验证报告（systems_compared/consistency/confidence/discrepancies） | 矩阵系统<2→跳过；置信度低→不阻断仅标记；根本性矛盾→回退S5（≤1次） |
| S7 | 孵化规划 | 蓝图 + 验证报告 + 交叉验证报告 | 孵化规划（phases/dependency_graph/minimum_viable_path） | 缺阶段1验收标准→FAIL（重试≤1次）；阶段间循环依赖→FAIL |
| S8 | 系统矩阵登记 | 全部产物 | 登记确认（system_id/paradigm_tags/relation_network/evolves_from） | 登记失败→降级（输出登记信息但未写入，不影响交付包） |

门控语义：每步 handler 先执行→gate 后验收（检查本步输出是否合格），非前置条件检查。
