# 42位专家圆桌运行机制

## 模块定位

弥补单一思考视角盲区，用于范式评估、同构挖掘、蓝图评审、系统缺陷排查。

**不是角色扮演讲故事，是多学科视角的结构化评审组件。**

## 专家构成

42位专家覆盖完整学科谱系：
- 数学类：数学、数论、统计学、逻辑学
- 物理类：物理学、凝聚态物理、热力学、量子力学
- 生物类：生物学、神经科学、生态学、进化论
- 计算机类：计算机科学、软件工程、人工智能、信息论
- 社会科学类：社会学、经济学、政治学、心理学
- 人文类：语言学、哲学、历史学、艺术理论
- 工程类：系统工程、控制论、机械工程、电子工程
- 其他：方法论管家（PI）、复杂系统专家、易经演化专家等

> 当前实际装备31位专家，581对同构关系已建立。

## 完整运行机制

### 1. 触发时机

触发场景（可选会诊环节，可开关）：
- 范式杂交评审
- 新系统蓝图评审
- 自优化方案评审
- 跨学科同构挖掘

不会每一步都调用，避免过度使用。

### 2. 任务分发机制

**子集筛选（关键设计）**：
- 根据当前任务标签，系统矩阵自动筛选匹配学科子集
- **不会无条件42人全部输出**
- 示例：
  - 做叙事动力学 → 优先调用语言学、社会学、复杂系统专家
  - 做动力学等价比对 → 优先数理类专家
  - 做系统架构评审 → 优先计算机、系统工程、控制论专家

**任务下发**：把待评审对象（范式文本/系统蓝图/候选优化方案）统一给到选中专家集合。

### 3. 专家个体工作逻辑

每一位专家内置：
- 该学科核心公理
- 惯用分析方法论
- 学科边界
- 常见谬误清单

**专家输出格式固定三部分**：
1. 本学科视角下的优势点
2. 本学科视角下的漏洞、矛盾、反例
3. 本学科推荐使用的分析方法论

> ❗重要约束：专家不会自由脑补幻想理论，输出必须依托范式库、方法论库已有内容。

### 4. 圆桌汇总收敛（关键步骤，避免信息爆炸）

圆桌不是直接把42份意见全部抛出，内置汇总收敛器：

1. **合并重复观点**：不同专家提出的相同/相似观点合并为一条
2. **标记观点冲突点**：区分事实矛盾、学科立场差异
3. **输出结构化圆桌报告**：
   - 共识清单
   - 风险清单
   - 分歧点清单
   - 推荐方法论集合

### 5. 输出对接下游组件

圆桌报告传递给：
- 系统验证器（作为评估输入材料）
- 方法论管家（根据专家意见推荐对应方法论）
- 自优化引擎（作为优化方案评审依据）

**不直接作为最终结论**，必须经过下游组件的进一步处理。

### 6. 缓存管理（V8新增）

- 单次会诊结束后，自动清理专家中间推演草稿
- 仅保留正式结论
- 减少上下文冗余，适配沙箱环境

## 元问题处理模式（V4.0升级）

当检测到战略/元问题（发展方向、下一步、路线图、优先级、战略、瓶颈、应该做什么等），自动切换到战略分析模式：

**战略分析发言框架**：
- 不再是"用XX方法"，而是"从XX视角：现状诊断→瓶颈识别→具体行动"
- 每个专家根据领域特性给出针对性分析

**PI决策型总结**：
- 【专家共识】提炼高频关键词
- 【P0 立即执行】有明确可执行行动的建议
- 【P1 接着推进】有方向但需准备的建议
- 【待验证分歧】质疑和反驳
- 【我的决策】PI给出明确下一步

**行动建议优先级排序**：
- P0：有明确动宾结构的可执行行动
- P1：有行动方向但需准备
- P2：只有分析框架

## 已知问题与优化方向

### 当前问题
1. expert_roundtable.py 文件体量92KB，单文件过大
2. 专家发言在某些场景仍有模板化倾向
3. 行动建议数在部分会议中为0（专家只给分析不给行动）

### 优化方向（暂缓，当前稳定）
1. 拆分expert_roundtable.py为多个模块
2. 增强专家发言的领域特化（每个专家在系统优化场景下的具体分析角度）
3. 优化优先级判定逻辑，避免全是P0

## 三个顾问角色

在自优化场景下，常设三个顾问角色：
1. **逻辑审计**：先理清概念和因果关系，检查循环论证
2. **方案搭配**：找杠杆点，排优先级
3. **盲区补全**：检查失败场景和二阶效应

方法论管家（PI）作为会议主持人，负责汇总、决策、推荐方法论。
