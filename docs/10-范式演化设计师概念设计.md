## 0. 项目上下文回顾

UHES 不是单一预测/问答系统,是**生成强大系统的元系统(系统生成器)**,由「系统生成器 + 理论融合器 + 架构进化器」构成,通过理论范式杂交产出可落地业务系统,实现"系统生成系统"递归闭环。全部设计受九条非侵入铁律约束:核心骨架冻结、双轨隔离、零共享资源、内存硬锁 60%、禁止修改原生 Prompt、分层注入动态加载、零未来信息、扩展能力默认关闭、完整单元测试与快照哈希链验证。

**本文档设计对象**:范式演化设计师 Agent 承接复杂现实问题,走「需求DNA解析→范式匹配/杂交→系统蓝图→8维验证→孵化规划→矩阵登记」完整流水线,输出带验证报告与落地里程碑的完整系统蓝图。它不直接执行业务,是元智能体。

## 2. 第一部分:需求 DNA 解析模块

### 2.1 输入(用户原始问题)

```
INPUT = {
  "raw_requirement": str,     # 用户输入的原始自然语言需求(必填)
  "context": {                # 可选补充上下文(全部可空)
    "domain_hint": str|null,       # 用户自报领域
    "stakeholders": [str],         # 利益相关方
    "existing_systems": [str],     # 用户已知的既有系统/工具
    "success_metric_hint": str|null # 用户心中的成功标准
  }
}
```

### 2.2 输出(需求 DNA 结构化 Schema)

```
REQUIREMENT_DNA = {
  "dna_version": "1.0",
  "parsed_at": "<ISO时间戳>",
  "goal": {
    "primary": str,              # 主目标(单句,动宾结构)
    "secondary_goals": [str],    # 次要目标(≤3)
    "success_criteria": [str],   # 可验证的成功判据(≥1);承载"可验证结果",与constraints分工见2.5
    "goal_source": "user_stated|derived|mixed"   # 目标来源标注:用户明说/推导得出/混合,推导目标须列入assumptions
  },
  "constraints": [
    {
      "type": "hard|soft",       # 硬约束(不可违反) vs 软约束(可权衡)
      "dimension": "time|cost|resource|technology|regulatory|ethics|other",
      "description": str,
      "source": "user_stated|derived"
    }
  ],
  "boundaries": {
    "in_scope": [str],
    "out_of_scope": [str],
    "unknown_zones": [str]       # 未明确区域,按最小化处理或需澄清
  },
  "risks": [
    {"risk": str, "severity": "high|medium|low", "trigger_condition": str}
  ],
  "ambiguities": [str],
  "assumptions": [
    {"assumption": str, "made_because": str}
  ],
  "paradigm_hints": [str]        # 初步范式倾向(基于领域词映射,可空)
}
```

### 2.3 解析算法(概念层,三步)

```
STEP A 目标抽取
  输入: raw_requirement
  动作: 提取主目标/次要目标/成功判据
  判定: primary为空 → FAIL(返回澄清问题,不进入下游)
  反例保护: 若存在互相矛盾目标(A与¬A),标记ambiguity,不做默认取舍

STEP B 约束与边界分离
  动作: 按8维度识别约束,区分硬/软;按in/out/unknown三桶拆分边界
  判定: 硬约束冲突 → 输出冲突清单,要求用户裁决,不静默放宽
        [P1-A2修复] 硬约束冲突不适用"最小假设降级":流水线进入 waiting_user 状态,
        暂停等待用户裁决,不自动继续;用户明确放弃某一硬约束并确认后,才可继续

STEP C 风险与歧义登记
  动作: 从约束组合推导风险;登记全部解析假设
  判定: 歧义>3个 → 澄清循环(阶段1最多1轮追问);
        仍不清晰 → 按最小可行假设显式标注并继续(防死锁)
```

### 2.4 设计归属

- 基于已有:01 记忆匣"需求DNA解析(目标、约束、边界、风险)"既有四字段。
- **新提出**:①约束硬/软二元分类与 8 维度枚举;②boundaries 三桶拆分;③assumptions 显式登记(呼应"严禁循环论证"铁律);④澄清循环轮数上限与降级策略(对应 01 分阶段计划)。

### 2.5 字段语义界定(演示微调项1落地)

**背景**:阶段1全链路演示(docs/11)实测发现,success_criteria 与 constraints 可能表达同一诉求(如"结论可溯源"),存在双写风险。

**界定规则**:
- `constraints` 承载 **技术实现约束**——系统在实现过程中"必须怎么做/不能怎么做"(如:必须保留原文锚点、必须运行于临时沙箱、必须支持四语)。
- `success_criteria` 承载 **可验证结果**——交付后"如何判断成功"(如:每条结论可回溯到原文句子级锚点、综述含不确定性标注)。
- 同一诉求的两面可以并存,但**表述必须分工**:一侧写实现方式,另一侧写验收形态,不得原样重复。
- 反例保护:解析时若检测到 success_criteria 与 constraints 出现语义重叠项,标记为"待去重"的 ambiguity,由解析器按上述分工原则合并,并在 parse_log 中记录合并动作。

## 3. 第二部分:范式匹配与杂交决策逻辑

### 3.1 模块定位

接收 REQUIREMENT_DNA,输出:匹配范式集合(含匹配度)、方法论管家推荐集合(含推荐权重)、杂交决策(是否/哪几个/深度)、可选专家圆桌触发。

### 3.2 匹配输入

```
MATCH_INPUT = {
  "dna": REQUIREMENT_DNA,
  "paradigm_catalog": [          # 29组范式库(概念引用,不复制)
    {"id": str, "name": str, "core_axioms": [str], "domain_tags": [str], "applicability": str}
  ],
  "enabled_depth": "structure_only|dynamics_equivalence"   # 扩展开关,默认structure_only
}
```

### 3.3 匹配算法(四步加权)

```
STEP 1 领域标签初筛
  输入: dna.paradigm_hints + dna.goal.primary + dna.constraints[].dimension
  动作: 领域关键词与范式domain_tags交集匹配
  输出: 候选范式子集(概念阈值:保留匹配度前50%,≤15个)
  防错: 初筛为空 → 降级全库扫描,标记"low_confidence_match"

STEP 2 核心公理语义匹配
  输入: 候选范式core_axioms vs dna.goal + dna.constraints
  评分维度(概念性):
    - axiom_coverage: 范式公理解释需求核心问题的能力
    - non_contradiction: 范式公理与需求硬约束是否冲突
    - transferability: 范式迁移到本需求领域的可行性
  输出: 匹配度等级 high/medium/low/rejected

STEP 3 方法论管家协同推荐
  输入: 匹配结果 + dna.ambiguities + dna.risks
  推荐权重机制(三信号,按优先级):
    信号1(最高): 需求DNA明确风险/歧义类型 → 直接映射方法论
      例: 公理冲突 → 强制「公理自洽性检查」;high级风险 → 强制「反例构造法」+「鲁棒性边界测试」
    信号2(中): 范式匹配结果的方法论偏好
      例: 物理类范式 → 「动力学建模」「约束流形构建」;社科类 → 「因果依赖链追溯」「网络拓扑表征」
    信号3(最低): 历史调用频次(仅参考)
      注: 沙箱计数不持久,此信号权重最低,避免被临时数据误导
  防错: 三信号皆无 → 保底推荐「第一性原理分析法」+「奥卡姆剃刀」
  输出: 推荐方法论列表,每条标注推荐信号与理由

STEP 4 杂交决策(三分支)
  分支A 单范式足够:
    条件: 仅1个范式high,公理覆盖率≥核心诉求
    动作: 不杂交,标记"single_paradigm"
  分支B 结构同构杂交(默认):
    条件: 2-3个范式≥medium,且存在已记录同构关系
    动作: 结构同构杂交,仅合并框架层级,不触碰动力学方程
  分支C 动力学等价杂交(扩展能力,需显式启用):
    条件: enabled_depth=dynamics_equivalence,且存在可验证的动力学等价关系
    动作: 动力学等价杂交;杂交后强制「公理自洽性检查」验证复合范式无内部矛盾
    防错: 等价关系无法验证 → 降级分支B,标记"dynamics_equivalence_not_verified"
```

### 3.4 匹配输出 Schema

```
MATCH_OUTPUT = {
  "matched_paradigms": [
    {"paradigm_id", "paradigm_name", "match_level": "high|medium|low",
     "match_rationale", "axiom_coverage_note", "contradictions": [str]}
  ],
  "recommended_methodologies": [
    {"methodology_id", "methodology_name",
     "category": "溯源|建模|验证|优化|协同",
     "recommendation_weight_signal": "signal_1_risk|signal_2_paradigm|signal_3_history|fallback",
     "recommendation_rationale"}
  ],
  "hybridization_decision": {
    "branch": "single|structure_hybrid|dynamics_hybrid|rejected",
    "selected_paradigm_ids": [str],
    "hybrid_depth": "none|structure|dynamics",
    "composite_paradigm": {
      "id", "name", "core_axioms_merged": [str],
      "source_paradigms": [str],
      "isomorphism_relations_used": [str],
      "self_consistency_checked": bool,
      "consistency_check_report": str
    } | null,
    "degradation_note": str|null
  },
  "expert_roundtable_trigger": {
    "should_trigger": bool,
    "trigger_reason": str|null,
    "recommended_expert_subset": [str]
  },
  "roundtable_skipped_audit": {        # [P1-C2修复] 未触发圆桌时的完整审计(正式字段)
    "confidence_basis": str,           # 匹配置信度依据
    "risk_assessment": str,            # 风险评估结果
    "skip_decision_rationale": str     # 跳过决策理由
  } | null,
  "match_confidence": "high|medium|low",
  "provenance": {
    "dna_ref": str, "paradigm_catalog_version": str, "methodology_catalog_version": str
  }
}
```

### 3.5 专家圆桌触发判定

```
触发条件(满足任一):
  1. ≥2个high级范式且核心公理存在冲突
  2. dna.risks存在≥1个high级风险
  3. 杂交决策为dynamics_hybrid(动力学杂交必须经圆桌评审)
  4. match_confidence=low
  5. 用户显式要求

不触发条件:
  - 单范式足够 + match_confidence=high + 无high级风险
  - 跳过时必须在02件MATCH_OUTPUT的 roundtable_skipped_audit 字段记录完整审计
    (confidence_basis / risk_assessment / skip_decision_rationale),保证可审计
```

- **新提出**:①四步加权匹配算法;②三信号推荐权重机制(补"权重从哪来"缺口);③杂交决策三分支与降级策略;④圆桌触发 5 条件 + 可审计跳过;⑤动力学杂交强制自洽校验。

## 4. 第三部分:完整工作流水线状态机

### 4.1 全局状态变量

```
PIPELINE_STATE = {
  "run_id": str,
  "started_at": "<ISO时间戳>",
  "current_step": str,
  "step_history": [
    {"step_name", "entered_at", "exited_at",
     "status": "passed|failed|degraded|skipped",
     "gate_decision", "degradation_note": str|null, "output_ref"}
  ],
  "artifacts": {
    "requirement_dna", "match_output", "roundtable_report",
    "blueprint", "validation_report", "cross_validation_report",
    "incubation_plan", "matrix_registration"     # 各为 object|null
  },
  "degradation_count": int,          # 降级计数
  "rollback_count": int,             # [P1-B2修复] 回退计数(正式字段):与degradation_count合并,
                                     # 合计≥3触发全局最短路径保护,防止连环重试绕过全局保护
  "user_interventions": [
    {"at_step", "intervention_type": "clarification|override|termination", "content"}
  ],
  "final_status": "running|completed|completed_with_degradation|failed|terminated_by_user"
}
```

### 4.2 八步状态机详解

**S1 需求DNA解析**
输入:INPUT → 处理:三步解析算法 → 输出:REQUIREMENT_DNA
门控:`goal.primary为空→FAIL(澄清)`;`硬约束冲突>0→FAIL(裁决)`;`歧义>3→澄清循环(阶段1最多1轮,超限按最小可行假设降级)`
失败分支:FAIL_CLARIFICATION(等待用户)、FAIL_CONSTRAINT_CONFLICT(等待用户裁决)
流转:PASS → S2

**S2 范式匹配与杂交决策**
输入:REQUIREMENT_DNA + 范式库引用 + enabled_depth → 处理:四步匹配算法 → 输出:MATCH_OUTPUT
门控:`matched_paradigms为空→FAIL(覆盖不足,建议扩充范式库,终止)`;`branch=rejected→FAIL(全冲突,终止)`;`match_confidence=low且未触发圆桌→强制触发圆桌`
失败分支:FAIL_PARADIGM_COVERAGEOUT、FAIL_ALL_PARADIGMS_CONFLICT
流转:PASS且触发圆桌 → S2.5;PASS且不触发 → S3

**S2.5 专家圆桌会诊(可选,按需加载)**
输入:MATCH_OUTPUT + REQUIREMENT_DNA + 推荐专家子集 → 处理:子集筛选→专家三部分输出→汇总收敛器 → 输出:roundtable_report(可能更新MATCH_OUTPUT)
门控:`圆桌指出根本性错误→回退S2(最多1次,第2次降级使用原匹配结果)`;`仅优化建议→采纳,PASS`;`圆桌超时/异常→跳过圆桌,标记degraded`
流转:PASS → S3
资源管理:圆桌结束清理中间草稿,仅保留正式报告,释放内存

**S3 方法论推荐确认**
输入:MATCH_OUTPUT.recommended_methodologies + roundtable_report(若有) → 处理:合并圆桌推荐→去重→按信号排序→绑定执行步骤模板 → 输出:最终方法论方案
门控:`推荐列表为空→降级保底(第一性原理+奥卡姆剃刀),标记degraded`;`存在与硬约束冲突的方法论→移除并记录`
流转:PASS → S4

**S4 蓝图生成**
输入:REQUIREMENT_DNA + MATCH_OUTPUT + 方法论方案 + 圆桌报告(若有) → 处理:注入理论基因→按方法论构建架构→自动注入范式标签 → 输出:系统架构蓝图
门控:`缺必填模块(输入/输出/验证)→FAIL(重试最多1次)`;`违反非侵入铁律→FAIL`;`与DNA硬约束冲突→FAIL`;`重试1次仍不通过→降级输出"不完整蓝图+缺陷清单",标记degraded,继续S5`
失败分支:FAIL_BLUEPRINT_INCOMPLETE、FAIL_BLUEPRINT_VIOLATES_CONSTRAINTS
流转:PASS → S5

**S5 系统验证(8维评分)**
输入:蓝图 + REQUIREMENT_DNA → 处理:8维评分 + 缺陷清单 + 可接入圆桌报告 → 输出:验证报告
8个验证维度(概念定义):
1. 需求覆盖度:蓝图是否覆盖DNA全部主/次要目标
2. 约束合规度:是否满足所有硬约束
3. 架构完整性:模块划分完整、数据流闭环
4. 非侵入合规度:是否遵守非侵入铁律
5. 可落地性:是否有明确工程落地路径
6. 可验证性:系统输出是否可被独立验证
7. 可扩展性:是否支持后续插件扩展
8. 风险可控性:是否识别并缓解DNA风险
门控:`critical缺陷→FAIL(回退S4最多1次,第2次降级带缺陷交付)`;`缺陷总数>概念阈值→建议回退S4`
流转:PASS → S6;FAIL且回退 → S4;FAIL且降级 → S6(带缺陷继续)

**S6 交叉验证(可选,按需加载)**

流转:PASS/跳过 → S7
资源管理:验证结束释放相关系统临时加载

**S7 孵化规划**
输入:蓝图 + 验证报告 + 交叉验证报告(若有) → 处理:分阶段里程碑(目标/交付物/验收标准/依赖/风险) → 输出:孵化规划
门控:`缺阶段1明确验收标准→FAIL(重试最多1次)`;`验收标准未逐条映射success_criteria→FAIL(微调项2落地:每条success_criteria须有对应验收条目,防止实现机制与验收脱钩)`;`阶段间循环依赖→FAIL`;`重试仍不通过→降级输出粗略里程碑,标记degraded`
流转:PASS → S8

**S8 系统矩阵登记**
输入:全部产物 → 处理:读取范式标签→登记(固定语义ID)→记录元数据→建立关系 → 输出:登记确认
门控:`登记失败(ID冲突/存储异常)→降级"输出登记信息但未实际写入矩阵",标记degraded(不影响交付包)`;`通过→PASS`
流转:PASS → 终态 COMPLETED
